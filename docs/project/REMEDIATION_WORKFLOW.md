# 项目修复工作流

本文把赛题要求、当前实现和后续修复拆成可逐项验收的任务。任务按风险和
赛题评分影响从高到低排列；每次只执行一项，完成自检和汇报后停下，等待确认
再进入下一项。

## 工作原则

1. 先补赛题硬要求和评分主项，再处理展示、文案和仓库整理。
2. 优先新增模块和接口；已有能力保持兼容。
3. `mcp_server/`、`skills/` 和正在运行的 W7 训练输入视为冻结区。除非任务
   明确列出无法绕开的修改理由，否则不修改、不删除、不重排这些目录。
4. 不进行全仓库格式化、换行转换或批量重写，避免把真实改动淹没在无关差异中。
5. 每项任务开始前写清改动边界，结束后报告改动文件、验收命令、结果、已知
   边界和下一项建议。
6. 每项任务保持可回退；涉及数据发布时先生成新快照，再原子切换活动指针。
7. 不把“能演示一次”当作“已验收”；未测能力明确写为待验证。

## 当前基线

- W1-W4：技术底座和确定性领域能力已形成。
- W5：单 Agent 已在 Nexent 实机运行，但原计划的三 Agent A2A 尚未实现。
- W6：多模态领域原型已通过，但尚未接入生产上传流水线和真实规模数据。
- W7：数据构建和教师标注已有进展，训练、主动学习、模型评测和边缘端
  性能仍在进行。
- W8-W10：动态本体、正式评测和离线交付尚未完成。
- 赛题要求的 Word 设计文档、完整截图、调用关系图和最终开源整理尚未形成。

## 优先级与任务拆分

### P0：赛题硬要求与核心评分项

#### R0 建立修复基线（本任务）

交付：

- 本工作流文档；
- 冻结区、兼容原则和逐项验收方式；
- 后续任务的优先级和依赖关系。

验收：

- 文档存在且与当前项目状态一致；
- 本任务不修改 `mcp_server/`、`skills/` 或 W7 训练输入；
- 下一项任务的输入、输出和回退边界明确。

#### R1 本体演化契约与版本存储

目标：补齐 W8 的不可变本体版本、变更单状态机和活动版本指针。

交付：

- 新增独立的 `lightrag/fault_tree/governance/` 模块；
- Ontology version store、change set、审核事件和活动指针契约；
- 原子写、路径校验、版本不可变和失败恢复测试；
- 不修改现有只读 MCP 工具。

验收：

- 相同内容重复写入幂等；
- 发布新版本不修改旧版本；
- 指针损坏或目标缺失时 fail closed；
- 旧版本仍可按版本标识读取；
- `tests/domain` 中新增目录测试通过。

#### R1.5 本体治理能力接入 Nexent

目标：让 R1 的治理能力通过用户唯一入口 Nexent 可见，而不是只存在于内部
Python API 和测试中。

交付：

- 新增独立 `ontology-governance` MCP，保持原领域 MCP 不变；
- 提供活动版本、历史版本、版本详情、变更单和审核时间线五类只读工具；
- Nexent Agent 声明第二个 MCP 服务器并加载治理工具；
- 导入流程在治理库为空时显式 bootstrap，已有状态不隐式重写；
- 系统提示词要求版本问题必须调用治理工具，不得根据领域数据猜测；
- 用户示例问答和故障排查文档。

验收：

- 用户可在 Nexent 中询问当前本体、历史版本和版本内容；
- 治理库未初始化时明确返回 `initialized=false`；
- 活动指针损坏时返回 `state_invalid`，不回退到旧版本；
- 领域 MCP 原 6 个工具、3 个 Skill 和行为保持不变；
- 两个 MCP 的 stdio/HTTP 传输、Agent bundle 和导入流程均有离线测试。

#### R2 标准文档到本体变更草案

目标：让上传标准节选后生成带逐字证据的候选类、关系、约束和 `gaps`。

交付：

- 新增 candidate extraction 模块或新 Skill；
- 复用 W6 解析结果和现有证据契约；
- 对每条候选保留文件、页码/行号、字符区间和 quote；
- 无证据候选进入待补证状态，不进入可审核集。

验收：

- 一份标准节选生成机器可读 diff；
- quote 全部可在来源文本中逐字定位；
- 不自动写入正式本体；
- 现有 `ontology_change_draft` Skill 行为保持不变。

#### R3 审核状态机、冲突和影响分析

目标：完成从草案到人工审核的结构化闭环。

交付：

- `draft -> under_review -> approved/rejected` 状态机；
- 审核人、理由、时间和内容哈希的追加式审计记录；
- 受影响租户、实体、事实、规则、故障树和测试的分析；
- 最小审核 API 或 CLI；本轮不要求完整前端。

验收：

- 阻断冲突无法批准；
- Agent 不能直接批准或发布；
- 重复审核幂等且不覆盖历史记录；
- 影响报告包含对象数量、样例 ID 和生成依据。

#### R4 迁移、发布和历史版本查询

目标：完成 W8 的实例迁移、原子发布、回滚和旧数据可查询。

交付：

- dry-run 迁移计划；
- 目标本体重新投影、校验和 Schema 更新；
- 新 run 完整生成后原子切换 `active.json`；
- 回滚只切换指针并保留审计；
- 旧 run/本体版本的只读查询入口。

验收：

- 迁移失败时旧版本继续服务；
- 发布成功后版本号递增且新数据可查询；
- 回滚后旧数据可查询且新快照仍保留；
- 不通过 `prune_tenant` 删除治理历史。

#### R5 Nexent 三 Agent A2A 编排

目标：实现主 Agent + 证据复核 Agent + 专家辅助 Agent，而不是只增加提示词。

交付：

- 三个 Agent 的声明式配置和独立提示词；
- `managed_agents` 关系、工具最小权限和输出契约；
- 新的多 Agent 导入入口，复用现有 Nexent 客户端；
- 离线 bundle、导入、循环检测和失败路径测试。

验收：

- Nexent 中只有一个主 Agent 和两个受限子 Agent；
- 子 Agent 不能互相递归调用；
- 主 Agent 仍负责最终答复；
- 辅助 Agent 失败时明确报告未完成，不静默降级；
- 现有单 Agent 导入入口保持可用。

#### R6 跨文档多跳业务闭环

目标：证明工业场景中的跨文档推理和决策溯源，不再只展示单次工具调用。

交付：

- 至少一条跨维修记录、手册和巡检表的链路；
- 每个中间结论都引用逐字证据；
- 明确展示多跳路径、拒绝条件和人工复核点；
- 可重复运行的一键演示脚本。

验收：

- 演示路径包含至少两次跨资产或跨文档跳转；
- 任一证据移除后，相应结论会被降级或拒绝；
- transcript 记录工具调用和证据 ID；
- 业务输出能与现有故障树/审核流程衔接。

### P1：效果、体验和提交证据

#### R7 W7 结果接入与主动学习闭环

目标：在训练完成后补齐低资源蒸馏的客观结果。

边界：

- 不改动正在运行的数据和配置；
- 训练产物完成后只增加评测和报告逻辑。

验收：

- 基座、学生、GGUF 的可比指标；
- 证据逐字率、实体/关系 F1、负样本空输出率；
- 目标域和跨域留出集分开报告；
- 低置信样本可进入审核队列。

#### R8 业务价值量化与评测

目标：把“可演示”提升为“可比较”。

交付：

- 固定评测集和随机种子；
- 检索、证据、故障树、端到端诊断指标；
- 单 Agent 与三 Agent、教师与学生、有无图谱的消融；
- 人工耗时、证据核验耗时和人工采纳率。

验收：

- 一条命令复现主要指标；
- 报告包含失败案例和限制；
- 结论与数字一致，不用单例外推整体效果。

#### R9 Nexent 配置固化与交互证据

目标：满足初赛对 Agent、模型、工具、知识库、调用关系图和截图的要求。

交付：

- 固定模型 ID/名称和 embedding 配置；
- Agent、工具、Skill、知识库和 MCP 调用关系图；
- Web UI 操作截图和示例问答；
- 配置字段与导入报告一一对应。

验收：

- 从零导入不依赖租户里“碰巧存在的第一个模型”；
- 图中每个节点都能在 JSON 或代码中找到对应；
- 截图来自实际运行版本，不是静态模拟。

#### R10 初赛设计文档与材料包

目标：形成可提交的 Word 设计文档和材料清单。

交付：

- 项目概述、整体方案、知识图谱构建、Agent 构建；
- 原始数据、处理流程、隐私边界和失败处理；
- 业务价值、创新点、示例问答和评测结果；
- JSON、知识库、MCP、Skill 和截图索引。

验收：

- 文档中的路径、版本和指标与仓库一致；
- 所有截图和 JSON 均能定位；
- 不包含版权受限标准原文或真实密钥。

#### R11 仓库卫生与开源整理

## 单项任务汇报模板

每项任务完成后按以下内容汇报：

1. 是否完成，以及完成边界；
2. 新增或修改的文件；
3. 为什么需要修改已有文件，以及如何避免行为变化；
4. 执行的验收命令和结果；
5. 对现有 MCP、Skill、W7 和用户数据的影响；
6. 仍未覆盖的边界；
7. 下一项建议，以及是否需要用户确认。
