# 工业设备故障诊断与本体治理项目成果

## 一、项目概述

本项目以 Nexent 作为唯一用户入口，基于 LightRAG 构建工业设备故障诊断与
本体治理系统。系统从设备手册、维修记录、巡检表、标准文件和图片中抽取
设备、故障、原因和证据，并给出带逐字来源的诊断结论、故障树位置和人工
复核意见。

项目解决三个核心问题：

1. 维修资料分散，故障原因难以快速定位；
2. 大模型回答容易缺少原文依据，难以审计；
3. 本体和故障树需要持续升级，但不能由模型直接修改或发布。

## 二、系统架构

```text
Nexent 对话界面
    │
    ▼
主 Agent
    ├── 证据复核 Agent
    └── 本体专家 Agent
    │
    ├── 领域 MCP：本体、设备、故障、证据、故障树
    ├── 治理 MCP：草案、审核、迁移、发布、回滚
    └── 上传 MCP：文件解析、小模型抽取、知识导入
    │
    ▼
工业故障本体、知识图谱、证据库、故障树、版本快照
```

Nexent 负责交互和任务编排；模型负责理解和候选抽取；确定性程序负责证据、
本体、Schema 和版本校验；人工负责最终审批。

## 三、已实现功能

| 功能 | 用户可见结果 |
|---|---|
| 文件上传 | 在 Nexent 中上传 PDF、CSV、XLSX、图片、Markdown 或 TXT |
| 资料解析 | 自动获得文件、页码、表格行、章节和字符位置 |
| 故障诊断 | 输入设备位号和症状，返回候选原因、证据和排查建议 |
| 逐字取证 | 每条结论显示 `evidence_id`、原文、来源和定位 |
| 故障树 | 展示 AND/OR 路径、逻辑门、顶层事件和分支覆盖 |
| 多智能体复核 | 证据 Agent 与本体 Agent 分别独立复核 |
| 本体变更 | 从标准原文生成机器可读的本体变更草案 |
| 审核发布 | 草案审核、影响分析、迁移 dry-run、发布和回滚 |
| 版本治理 | 保留不可变本体版本、Schema、审核记录和租户快照 |
| 本地抽取 | 使用微调的 Qwen2.5-1.5B 学生模型进行结构化抽取 |

### 1. 证据约束诊断

系统不会让模型直接回答后“补引用”。诊断流程为：

```text
设备确认
→ 检索候选故障
→ 读取故障树
→ 对实体、事实和规则逐条取证
→ 校验 quote、哈希和字符区间
→ 子 Agent 复核
→ 主 Agent 输出结论
```

证据不足时，系统明确返回“待验证”或“证据缺口”，不把候选原因写成已确认
故障。

### 2. 多模态知识导入

系统可解析：

- PDF 逐页文本；
- CSV 行；
- XLSX 工作表和行；
- PNG/JPEG 中文图片转写；
- Markdown/TXT。

解析结果进入统一的设备、故障、事实、规则、证据和故障树模型，而不是只作为
普通知识库文件。

用户上传文件后，可以直接在 Nexent 中让 Agent 识别、导入和查询。领域服务
会热刷新活动快照，不需要重启。

### 3. 三智能体协作

- 主 Agent：理解问题、调用工具、组织最终答复；
- 证据复核 Agent：检查 quote、来源、引用方向、悬空对象和故障树缺项；
- 本体专家 Agent：检查类、关系、约束、冲突、Schema 和迁移影响。

两个子 Agent 均已在 Nexent 中发生真实调用。子 Agent 不能批准、发布或
回滚本体。

### 4. 本体演化闭环

系统支持：

```text
draft
→ under_review
→ approved / rejected
→ migrated
→ published
→ rolled_back
```

发布前必须执行迁移 dry-run。发布后生成版本化 JSON Schema，并原子切换
租户快照。回滚不删除新旧版本，历史仍可查询。

## 四、关键优化

### 1. 普通 RAG 升级为“图谱 + 证据 + 故障树”

普通 RAG 只返回相似文本。本系统同时返回设备、故障、原因规则、AND/OR 门、
故障树路径和逐字证据。

P-101A 场景中：

- 纯词法检索：故障命中率 1.0，证据覆盖率 0；
- 完整图谱路径：故障命中率、证据覆盖率、quote 哈希和字符区间有效率均为 1.0；
- 故障树结构和原因分支覆盖率匹配。

### 2. 模型与确定性程序分工

| 任务 | 执行者 |
|---|---|
| 自然语言理解、候选抽取 | 大模型/小模型 |
| 本体类型、关系和约束校验 | 确定性程序 |
| 证据 quote、哈希和区间校验 | 确定性程序 |
| 迁移、版本发布和回滚 | 治理服务 |
| 最终批准和发布 | 人工 |

该设计避免单一模型同时承担诊断、审批和审计职责。

### 3. 本地小模型替代通用大模型抽取

学生模型由 Qwen2.5-1.5B-Instruct 经 QLoRA 微调得到，输入设备资料片段，
输出 `FaultEvent + CAUSES + 逐字证据`。

与通用基座相比：

| 指标 | 基座 | 微调后 |
|---|---:|---:|
| JSON 合法率 | 0.9678 | 1.0000 |
| Contract 合法率 | 0.0015 | 0.9801 |
| 实体 F1 | 0.1702 | 0.6841 |
| 关系 F1 | 0.0000 | 0.5212 |
| 逐字证据率 | 0.8136 | 0.9824 |
| 负样本准确率 | 0.0255 | 0.9745 |
| 平均输出 tokens | 337.90 | 92.13 |

平均输出长度下降约 73%，更适合本地部署。

分组结果：

| 测试组 | 实体 F1 | 关系 F1 | 证据率 |
|---|---:|---:|---:|
| CFDK 自由维修文本 588 条 | 0.6325 | 0.1910 | 0.9875 |
| 结构化中文泵手册 64 条 | 0.9845 | 0.9767 | 0.9545 |

结论：

- 微调显著改善了格式、实体、因果关系、负样本和输出效率；
- 在结构化中文设备资料上效果突出；
- 自由维修文本的复杂跨句关系抽取仍是当前难点；
- 模型只作为候选抽取器，正式知识仍需证据和人工审核。

### 4. 证据质量由硬约束保证

进入正式知识的数据必须满足：

- quote 是原文连续子串；
- quote 哈希一致；
- 字符区间一致；
- 来源资产存在；
- 引用目标存在；
- 关系方向正确。

不合规内容进入审核队列或被拒绝，不进入活动知识快照。

### 5. 上传后即时生效

新资料发布为不可变租户快照。领域 MCP 自动检测活动指针变化并刷新索引，
用户可以继续在同一对话中查询，无需重启服务。

### 6. 本体版本可追溯

每次变更保留：

- 标准原文和逐字证据；
- 变更操作和 diff；
- 审核人、原因和时间；
- 内容 SHA-256；
- 版本化 JSON Schema；
- 租户迁移快照；
- 发布和回滚记录。


## 六、效果演示

设备：P-101A 冷却水泵。

问题：

> 出口压力不足，可能原因有哪些？请给出证据出处和故障树位置。

系统返回：

- 入口过滤器堵塞，证据较完整；
- 叶轮汽蚀，有手册机理但缺少现场验证；
- 故障树：

```text
出口压力不足
→ OR
  ├── 入口过滤器堵塞
  └── 叶轮汽蚀
```

- 明确说明缺少清理后压力恢复、振动或 NPSH 实测；
- 给出清理过滤器、复测压力等下一步排查建议。

该流程同时展示故障诊断、证据追溯、故障树和不确定性表达。

## 八、创新点

1. **证据门控诊断**：证据在校验阶段参与，不是回答后补引用。
2. **多智能体职责分离**：主 Agent、证据 Agent、本体 Agent 权限独立。
3. **模型与规则协同**：小模型负责抽取，确定性工具负责校验和治理。
4. **本体演化可审计**：草案、审核、Schema、迁移、发布和回滚全部留痕。
5. **真实用户入口**：上传、诊断、审核和回滚均在 Nexent 内完成。
6. **独立评测数据**：使用未参与模型选择的新中文资料验证泛化基础。

## 九、业务价值

- 减少工程师跨文档查找和人工比对；
- 诊断结论带逐字证据，便于复核和审计；
- 新资料可以直接进入知识体系；
- 本体升级有审核、版本和回滚保障；
- 本地小模型降低外部 API 依赖，适合隐私要求高的工业环境；
- 证据不足时主动降级，降低错误确认风险。

## 十、结论

项目已经完成从资料上传、结构化抽取、证据校验、知识图谱、故障诊断、
多智能体复核，到本体审核、发布和回滚的完整闭环。

核心价值是：每条用户可采用的结论都能追溯到原文，并经过确定性校验；
每次本体变化都能审核、版本化和回滚；模型用于提高效率，但不拥有最终审批权。
