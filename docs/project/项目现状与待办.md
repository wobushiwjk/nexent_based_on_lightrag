## 二、已经完成的工作

用户通过 Nexent 对话界面即可完成：

- 上传 PDF、CSV、XLSX、PNG/JPEG、Markdown 和 TXT；
- 查询设备、故障原因和维修措施；
- 查看逐字证据、来源文件和定位；

- 调用证据复核和本体专家两个子 Agent；
- 从标准原文生成本体变更草案；
- 审核、发布和回滚本体版本。

### 2. 工业故障领域底座

已经完成：

- 可校验的工业故障本体；
- 9 个类、11 条关系和 8 条约束；
- IEC 61025、ISO 14224、IEC 60812、ISO 13374 标准映射；
- 7 份 JSON Schema 及哈希 manifest；
- 设备、故障、事实、规则、证据和故障树契约；
- 版本化租户快照和 SQLite 证据库；
- 活动指针原子切换。

### 3. 证据约束诊断

诊断链路已经实现：

```text
确认设备
→ 检索候选故障
→ 读取故障树
→ 对实体、事实和规则逐条取证
→ 校验 quote、哈希和字符区间
→ 子 Agent 复核
→ 主 Agent 输出结论
```

系统对于证据不足、未知设备、未知故障和工具失败都有明确的降级结果。

### 5. 多智能体协作

已经形成：

- 证据复核 Agent；

当前协作机制是 Nexent Managed Agents，不是外部 A2A Server。

需要完成：

- 修改已有类时重建对应 Schema definition；
- 更新 `oneOf`、discriminator 和 domain bundle union；
- 对受影响实例生成迁移计划；
- 新增必填属性前执行 backfill；
- 迁移后重新校验所有受影响 bundle。

验收：

- `ontology.yml` 与版本化 Schema 的类属性完全一致；
- 新必填字段在发布前不存在未补齐实例；
- 属性变更、迁移和回滚均可重复执行。
