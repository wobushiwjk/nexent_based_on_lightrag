# 医疗设备领域包（占位）

状态：**未实现**。这里只固定迁移边界，避免把工业领域的类名、字段或证据规则
误当成医疗领域的既成事实。等 W8/W9 的迁移验证通过后，再补充 `ontology.yml`、
crosswalk、种子文档和 gold bundle。

## 迁移假设

工业故障诊断与医疗设备故障/不良事件分析共享的是“上层协议”，不是术语本身：

| 工业故障包 | 医疗设备迁移候选 | 说明 |
| --- | --- | --- |
| `Equipment` | 医疗设备 / 资产 | 设备位号可复用为资产编号 |
| `FaultEvent` | 故障事件 / 不良事件 | 保持“事件”语义，不混入患者信息 |
| `FaultCauseRule` | 原因规则 | AND/OR 表达式可复用 |
| `Evidence` | 证据片段 | 逐字 quote、字符区间、哈希规则不变 |
| `File` | 说明书 / 维修记录 / 不良事件报告 | 载体类型不同，证据模型相同 |
| `Department` | 科室 / 厂商 | 组织容器，不参与因果推理 |

需要新增或改名的部分：

- 医疗设备分类、风险等级、患者安全影响等字段。
- 适用的监管术语和标准映射（例如医疗器械不良事件报告相关规范），
  不能直接套用 IEC 61025 / ISO 14224 的结论。
- 数据脱敏规则：任何患者标识都不得进入实体、证据或日志。

## 验收门槛

只有同时满足以下条件，才把本目录从占位升级为领域包：

1. `ontology.yml` 通过 `OntologyRegistry` 加载，版本号与 prompt 投影一致。
2. 至少 3 份医疗语料，证据 quote 全部逐字匹配源文件。
3. 一棵人工确认的 AND/OR gold 树，`python scripts/validate_domain.py --pack ...`
   零 error。
4. `tests/domain` 新增医疗包的回归测试，并证明去掉证据或制造环时校验会失败。
5. 同一套 MCP 工具和 Skill 不改代码即可读取医疗包（只换领域包）。
